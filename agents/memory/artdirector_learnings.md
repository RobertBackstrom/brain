## 2026-05-09 — knives_and_gutters — prompt-engineering
Flux.dev + fast-SDXL alone are insufficient for niche-named-artist styles. The K&G dry-run (24 images, 12 Flux + 12 fast-SDXL) burned ~$0.36 and landed off-target — Robert flagged "off from what I expected" — when the brief cited Gary Chalk + John Blanche + 80s-tabletop-tooling. **Why:** these models' training data is heavy on modern fantasy art and weak on pre-2000 tabletop traditions; they default toward generic AI-fantasy when given Chalk/Blanche/Frazetta-era/Brom-era/Larry Elmore/Jeff Easley/Russ Nicholson cues. **How to apply:** for projects citing those traditions, promote Lane C (Midjourney) and/or Lane D (Civitai LoRA, e.g. tabletop-art LoRA on fal.ai) to **co-primary** with fal-ai, not fallback. Update [ai_image_tool_matrix.md](../../skills/ai_image_tool_matrix.md) "Lane combinations for logos" section accordingly.

## 2026-05-09 — knives_and_gutters — process
**Diagnostic-before-re-roll protocol.** When the first AI concept pass lands off-target, don't re-roll blind. Run a 5-question diagnostic separating fundamental from tunable: (1) **mark vs scene** — wordmark badge or fantasy illustration with text on top? (2) **what style did it land in instead** of the named target? (3) **worst single offense** — pick one: too clean / too modern / too AI-generic / wrong palette / wrong era / mark-not-illustration / wordmark-illegible / other. (4) **anything 30% there?** — single seed worth reacting to. (5) **recalibration ref** — one image (any source) closer to what's in Robert's head. **Why:** "what was wrong?" gets vague answers; multiple-choice + reaction-anchor questions surface the actual gap fast. **How to apply:** add as a pipeline rule in artdirector.md between step 6 (curation) and step 7 (finalization). Don't accept a "this is off" without running the diagnostic first.

## 2026-05-23 — aurora_punks_pechakucha — prompt-engineering
**Blanche-style prompting without naming Blanche.** For gothic ink-wash illustration briefs, avoid citing "John Blanche" directly in prompts (model training varies; the name often produces pastiche GW-miniature painting, not the occult-distorted-figure quality Robert wants). Instead use: `ink-wash gothic illustration, distorted figures, occult aesthetic, rough paper texture, visible ink grain, surreal slightly elongated proportions, masterwork illustration`. Add `--style raw` in MJ v6 to suppress over-polishing. This produced better results for the AP Pecha Kucha brief than a named-artist cue would have.

## 2026-05-23 — aurora_punks_pechakucha — prompt-engineering
**Beautiful darkness palette encoding.** The "beautiful darkness" aesthetic translates reliably into prompts as: `deep Prussian blue (#0d1b2a), oxblood red (#6b1a1a), bone white highlights, aged gold accent used sparingly, amber candlelight/ember as sole warm light source, deep shadow dominant`. The key move is specifying the light SOURCE (candle, ember, lantern) rather than describing the overall image as "dark" - the former gives the model a compositional hook; the latter produces mud.

## 2026-05-23 — aurora_punks_pechakucha — brief-authoring
**Pecha Kucha visual density pattern.** 20 slides at 20 seconds = 11 unique generated images is the right ratio when 4 slides share a text-background plate and 1 cover image is reused as close slides. Generates enough visual variety without over-taxing Robert's curation time. Seed-linking 3-4 emotionally connected slides (origin, pivot, scars, starting-over) to a single anchor seed gives the deck a spine without making the brief feel constrained. Document reuse index at the top of the brief - Robert will re-reference it constantly during construction.

## 2026-05-23 — aurora_punks_pechakucha — process
**Anchor-seed generation order.** For decks with a visual through-line, always generate the hero/cover image first. Extract the seed. Pass that seed to emotionally adjacent slides (in this case: gothic figure on Slides 11/14/17 all shared Slide 1's seed). This gives a "same-world" feeling across slides without needing a custom LoRA. MJ v6 seed propagation is robust enough for this pattern when the prompts are structurally similar (same palette cues, same `--style raw` flag).

## 2026-05-23 — aurora_punks_pechakucha — prompt-engineering
**MJ v6 to Flux.dev adaptation pattern.** Strip: `--ar 16:9`, `--style raw`, `--v 6`, `--seed N`. Fold into natural language: aspect ratio via `image_size: "landscape_16_9"` API parameter; `--style raw` becomes `"avoid over-rendering, avoid smooth AI-generated sheen, avoid clean vector lines, rough paper grain dominant"` appended to every prompt; seed via API `seed` parameter. Preserve all palette hex codes verbatim - Flux reads them reliably. Adding `"no clean vector lines, no photorealism, no smooth sheen"` as explicit negatives works better than the `--no` MJ flag equivalent. Total prompt length 500-800 chars is the sweet spot for Flux.dev; above 1000 chars the model starts averaging instructions rather than following them hierarchically.

## 2026-05-23 — aurora_punks_pechakucha — process
**Slides API: skip it, use Drive folder + manual drag-in.** The Google Slides API image insertion (createImage request) requires a publicly accessible URL - it won't accept Drive file IDs directly. The workaround (make files public, get direct URL, then insert) adds complexity and a security step (making images public) that is unnecessary for a one-person drag-in job. The right default for presentation decks: upload all PNGs to the same Drive folder as the deck, report the folder URL, let Robert drag them in. Estimated manual drag-in time for 13 images: under 5 minutes. Don't burn Slides API time when Drive proximity + manual is faster end-to-end.

## 2026-06-18 — teef — compositing techniques (no numpy)
**Project:** teef
- **Green-screen key without numpy:** generate the asset (e.g. a red phone box) on a flat chroma-green bg via Flux, then key with `PIL.ImageMath.eval("255*((g>80)&(g>(r+25))&(g>(b+25)))", ...)`, invert to alpha, GaussianBlur(1.2) the alpha to feather, `crop(getbbox())`. Reliable on this box (numpy is NOT installed on the VPS; use ImageMath/point/ImageChops instead).
- **Scale a composited prop to scene:** a K6 phone box is ~1.5x human height; size it to ~1.5x a nearby figure's pixel height, add a blurred contact-shadow ellipse + a flipped 22%-alpha reflection + a soft red ground-glow for wet-street integration.
- **Pillow gotcha that ate an overlay:** `ov = Image.alpha_composite(ov, layer)` returns a NEW image, orphaning any `ImageDraw.Draw(ov)` bound earlier - subsequent `d.text/d.line` then draw onto the dead object and vanish. Use the in-place METHOD `ov.alpha_composite(layer)` so `d` stays valid, or rebind `d` after each composite.
- **Visualising an engine-only feature (camera-relative transparency):** Flux won't render true see-through. Do an annotated diagram instead: blend an occluding building region toward flat tone (polygon mask via `Image.composite`), overlay a cyan wireframe grid clipped to the mask, draw the revealed player + target ring ON TOP, add callout panels with leader lines. Honest + reads in a pitch.
- **Match a real landmark from a reference photo:** Flux's generic "Chinese archway" was wrong; describing the actual London Wardour St gate (three tiered green-and-gold glazed pagoda roofs, dragon finials, gold signboard with red characters, painted red/gold/blue/green dougong beams) got it accurate.
