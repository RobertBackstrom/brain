# Ticker Agent Learnings

## Data Sources

- **Never assert listing status or price from training memory.** I confidently told Robert "SpaceX
  has no public stock" — it had IPO'd on Nasdaq (SPCX) on 2026-06-12, days before, past my cutoff.
  Always run a live `WebSearch` + a `ticker-data.js quote` before making any claim about whether/where
  something trades or where it's priced. [ticker, 2026-06-16, process]
- **Yahoo Finance free endpoint, transport matters.** `query1`/`query2.finance.yahoo.com/v8/finance/chart/<sym>`
  works with no key and covers US + Stockholm (`.ST` suffix) + 52w hi/lo + OHLC for vol math. But:
  - Node's built-in `fetch` (undici) gets **429 regardless of headers** — Yahoo fingerprints the TLS/HTTP2
    client. Routing through **curl** (`execFile`) works. ticker-data.js uses curl. [ticker, 2026-06-16, tooling]
  - There's a **low per-IP burst cap.** Hammering it (or a 27-symbol batch fired at once) trips
    "Too Many Requests". Mitigations in place: concurrency 2, exponential backoff, query1/query2 rotation,
    one chart call per symbol in the digest. Real fix = EODHD upgrade. [ticker, 2026-06-16, tooling]
  - Stooq is no longer usable headless (JS proof-of-work wall as of 2026-06). [ticker, 2026-06-16, tooling]
- **SPCX is a newborn (IPO 2026-06-12).** Only a handful of daily bars, so 1mo/3mo volatility is `null`
  / meaningless for now. 52w hi/lo just reflects its 3-day life (hit ~$225.64 intraday by 2026-06-16,
  IPO priced $135, opened $150, day-1 close $160.95). Treat any vol/technical read on it as unreliable
  until it has ~20+ bars. [ticker, 2026-06-16, market]

## Volatility Math

- Historical vol = annualized stdev of daily log returns, ×√252. Sanity check from real pulls
  (2026-06-16): Paradox (PDX.ST) ~30% annualized, Evolution (EVO.ST) ~30%. Mid-cap Nordic gaming/tech
  sits roughly 25–35% in calm markets; a reading well above that flags a catalyst or a thin name.
  [ticker, 2026-06-16, reference]
- `posInRange` (0 = period low, 100 = period high) is a quick "where in the range are we" gauge for
  framing entries vs targets. [ticker, 2026-06-16, reference]

## Execution / Broker

- For a private person trading **both US + Swedish** equities via API: realistic options are
  **Interactive Brokers** and **Saxo Bank OpenAPI**. Nordnet's API is closed to new customers; Avanza

## Execution Infrastructure (Phase 2 build)

- **Building API wrappers ahead of credentials.** When the broker account isn't set up yet but the work can proceed, build the full wrapper structure with proper error messages for missing config. This lets you validate the design + OAuth flow + endpoint mapping against documentation, and the code is ready the moment credentials land. Pattern: env-var guards at the top, clear error messages with links to setup docs. [ticker, 2026-06-17, process]
- **Saxo OpenAPI structure.** Base URLs: `https://gateway.saxobank.com/sim/openapi` (SIM) and `https://gateway.saxobank.com/openapi` (live). Auth: OAuth 2.0 refresh-token flow with AppKey (client_id) + AppSecret (client_secret). SIM app is free + instant at developer.saxo; live needs account approval but is a separate setup step. Order placement: `POST /trade/v2/orders` with Uic (instrument code from search), AccountKey, BuySell, Amount, OrderType, OrderPrice. Separate docs at [developer.saxo/openapi](https://www.developer.saxo/openapi/referencedocs) and [order placement guide](https://developer.saxobank.com/openapi/learn/order-placement). [ticker, 2026-06-17, tooling]
- **Risk limits config for trading systems.** Caps belong in a JSON config, not hardcoded: per-order % of account, daily notional limit, max open positions, allowed order types, symbol allowlist (linked to the watchlist). Also: kill switch as a file check (`ticker/HALT`), client-order-ID prefix for idempotency, and an explicit live-enable flag that defaults false. This makes the limits auditable + tunable without touching code. [ticker, 2026-06-17, tooling]
- **SIM/live env separation.** Treat SIM and live as **fully separate environments** - different base URLs, different credentials, different refresh tokens (persisted to separate files). An env var (`SAXO_ENV=sim|live`) switches everything. The risk_limits.json has an `environments.live.enabled` flag that defaults false - even if live credentials exist, the code won't use them until Robert flips that after the SIM week. [ticker, 2026-06-17, process]
- **Audit trail for financial operations.** Every action that touches money - order placed, filled, rejected, cancelled - appends one CSV line (timestamp, action, symbol, side, quantity, price, order_id, env) to a durable log (`ticker/trades_log.csv`). Append-only, never modified. This is the ground truth for what actually happened, independent of what the broker or Death Board say. [ticker, 2026-06-17, process]

## Saxo Execution (proven 2026-06-17)

- **SIM app has no market-data license:** Saxo `infoprices` returns `PriceTypeAsk/Bid: NoAccess`,
  `Amount: 0`. So DO NOT rely on Saxo for quotes — price limit orders off the free Yahoo feed
  (`ticker-data.js`). Saxo is execution-only in our architecture. [ticker, 2026-06-17, tooling]
- **TooFarFromMarket:** Saxo rejects limit orders too far from current market. A Buy limit ~5% below
  market is accepted and won't fill instantly (used for the smoke test). Always derive the test/limit
  price from a real quote. [ticker, 2026-06-17, tooling]
- **OAuth confirmed:** SIM auth host `sim.logonvalidation.net` (authorize + token), gateway
  `gateway.saxobank.com/sim/openapi` — matches the app's own endpoint display. Code grant: AppKey +
  AppSecret via HTTP Basic at token endpoint; refresh token persisted to `.saxo_tokens_sim.json` (0600),
  auto-refreshed. First token minted via `auth-url` → browser approve → `exchange "<redirected-url>"`.
  [ticker, 2026-06-17, tooling]
- **Account identifiers (SIM):** ClientKey = AccountKey = `-RIfpPVqdkq7mdHXNDEwGw==` (single-account
  SIM). NVDA uic 1249 (NASDAQ), AAPL uic 211. [ticker, 2026-06-17, reference]
