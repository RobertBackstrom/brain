When intro'ing a prospective contractor (vendor, freelancer, partner studio) into one of Robert's projects, the introduction email and any pre-signature comms must NOT name:
- The IP / game / franchise (e.g. "Kingdom Two Crowns", "Sands of Duat")
- The client / publisher (e.g. "Raw Fury")
- The project codename / Jira prefix
- Any specific platform commitments or release dates that would identify the deal

Use generic descriptors instead: "DLC for a known pixel-art IP", "co-dev for a published franchise", "console title we're scoping", etc.

**Why:** Robert called this out on 2026-04-27 mid-thread when the K2C Lost-Hive intro draft named the franchise + publisher before Eamonn had even seen an NDA. Pre-signature leakage of IP / client identifiers is both a legal risk (potential breach of Robert's NDA with the publisher) and a commercial one (other parties learning Robert's deal mix).

**How to apply:**
- For new-contractor intros: write the email referring only to "the upcoming DLC" / "the project" / "a [genre] IP" until the MNDA is back signed
- Once MNDA is signed: the contractor moves to the same comms tier as the existing team and full project naming is fine
- The MNDA file itself can be named with project context internally (Robert's side), but the file shared with the counterparty before signing should also use generic naming where possible
- Pair this with [[reference_contract_templates]] — the MNDA itself goes from `czp_legal/templates/MNDA/` master into the project's legal folder, signed before the IP is named in any further comms.
