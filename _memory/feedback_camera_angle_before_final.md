For any game/environment art concept, **never create a final concept before the camera angle is set with Robert.** Generate cheap, clean (no-UI) camera-angle options first, let Robert pick the angle, and only then finalise the chosen frame (HUD overlay, pitch embed, upscale).

**Why:** On the Teef Chinatown concept I generated, HUD-composited and embedded several "final" shots across multiple rounds before Robert flagged the camera angle was still wrong vs the game prototype. Camera angle is foundational; finalising before it's locked wastes rounds.

**How to apply:** Treat camera angle like a Plan-Confirm-Execute gate for art. Match the angle to the source of truth (e.g. the live prototype) and confirm it explicitly before any UI/finalisation. See [[feedback_plan_confirm_execute]], [[feedback_ui_references_upfront]]. ArtDirector learning logged under teef.
