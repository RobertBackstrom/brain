The tunnel-fronted services on `runatyr.games`:

- **`board.runatyr.games`** — Kanban board (Death Board), served from `assistant/kanban.html` via `server.js`. **Gated by CF Access** (since 2026-04-23). Webhook paths `/webhook/atlassian` + `/webhook/docuseal` need path-level Bypass policies (HMAC-signed at origin). NOT `assistant.runatyr.games` — that hostname does not exist and referencing it has caused alert spam before (db-029).
- **`kanban.aurorapunks.com`** — MIRROR of `board.runatyr.games`, **COMPLETE 2026-07-15**. Tunnel ingress → `:3777` + proxied DNS CNAME → tunnel + added as a 2nd domain on the **existing** "Board (Death Board server)" Access app (id `2d66f8f2-…`, AUD `f3f74313…`, policy "Robert Only"). All three steps done from the VPS via CF API. Behaves identically to `board.` (Access login → board). The new Access-scoped token is `cloudflare.api.access` in the secrets registry. Rule for future mirrors: add the hostname to the EXISTING app (keeps the AUD the origin gate already trusts), never a separate app.
- **`hive.runatyr.games`** — RETIRED 2026-06-21 (db-223). The Hive (cc-hive Next.js honeycomb) was stopped/disabled and consolidated into the kanban; the subdomain now **serves the board** (tunnel ingress repointed to `:3777`, same content as `board.`). Don't tell anyone to "go to the Hive" — it IS the board now. Source saved at `github.com/RobertBackstrom/cc-hive` (private); cc-hive dir + build still on the VPS, marked reclaimable. Gated by CF Access (shares board's interactive policy).
- **`plane.runatyr.games`** — KILLED 2026-06-22 (db-223). Hostname fully decommissioned: tunnel route removed + DNS CNAME deleted, no longer resolves. (Self-hosted Plane CE was stopped/disabled first.) Config saved at `github.com/RobertBackstrom/plane-selfhost` (private; secrets redacted). Docker images (~12.6 GB) + volumes (~2 GB) still on VPS, marked reclaimable. NOTE: there is no `plane.runatyr.games` Access app (confirmed via dashboard) — but the `board-webhook-plane` *bypass* app (on `board.runatyr.games/webhook/plane`) is now orphaned by the retirement; delete it manually in Zero Trust for tidiness (VPS token has no Access scope).
- **`internal.aurorapunks.com`** — Internal portal / identity-aware launcher, **LIVE 2026-07-15**. Served from `assistant/internal.html` via `server.js` `/internal` (same `:3777` origin as the board). Reads the CF-Access-verified email (`getCfAccessEmail` → JWT `email` claim) and renders only entitled tiles via `assistant/internal-access.json` (roles/people/grants) through `/api/internal/tiles`. Wired from the VPS via CF API: ingress rule → `:3777`, proxied DNS CNAME, and added as a 3rd domain on the **existing** "Board (Death Board server)" Access app (id `2d66f8f2-d015-4320-a4f3-444e68c68c7c`, AUD `f3f74313…`) — same "add to existing app, keep the AUD" rule as the kanban mirror. Access changes used `CLOUDFLARE_ACCESS_API_TOKEN` (the Access-scoped token in `.env`). Owner-only until board/team/prospect emails are added to the access map. aurorapunks.com zone id `cb4386a8673f0822e8397a787a094eab`.
- **`code.runatyr.games`** — code-server IDE (VS Code in browser), for session launches from kanban cards. **Gated by CF Access** (from inception).
- **`pitch.runatyr.games`** — Static host for BizDev pitch one-pagers, URL scheme `/<slug>` → `pitches/<slug>/index.html`. **Fully public** (intentional — shareable prospect links). First slug live: `/1993` (1993 Space Machine → Pixel Helix, db-042).

**Auth posture (2026-04-24):** IdP is Google SSO with Apple SSO planned as the target per `ops-security-hardening-runbook-2026-04-24.md` (Google retained as fallback during cutover). Origin-side JWT verification middleware exists in `server.js` and activates when `CF_ACCESS_ENFORCE=1` is set in `.env` (**now ON, verified 2026-07-15** — was off when this memory was first written). This means any hostname routed to `:3777` without a valid Access JWT for `CF_ACCESS_AUD` gets 401'd at the origin, so a new mirror hostname can't accidentally expose the board before its Access app is set up.

**Source of truth caveat:** the `deathboard` tunnel is dashboard-managed (remote config), not local `~/.cloudflared/config.yml`. To see the actual live ingress on the VPS, check `journalctl -u cloudflared | grep "Updated to new"` — last line shows the dashboard-pushed config. To ADD or EDIT a public hostname, either use Cloudflare Zero Trust → Networks → Tunnels → `deathboard` → **Published application routes** tab (NOT Hostname routes Beta, which is WARP-gated), OR — confirmed working 2026-07-15 — do it programmatically with the VPS `CLOUDFLARE_API_TOKEN`: GET/PUT `/accounts/{acct}/cfd_tunnel/{tunnel}/configurations` (append an ingress rule) + POST a proxied DNS CNAME to `{tunnel}.cfargotunnel.com`. The VPS token covers Tunnel + DNS but **NOT Access** (Access changes still need the dashboard or an Access-scoped token). See DevOps learnings 2026-04-20 for the full playbook.
