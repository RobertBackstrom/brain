# Claude Cowork Methodology

**Source:** [LinkedIn post by Basia Kubicka](https://www.linkedin.com/posts/basiakubicka_most-people-use-claude-like-a-vending-machine-share-7451337055957188608-Ia32)

**Author:** Basia Kubicka

**Date captured:** 2026-04-25

## Summary

External validation of structured context approach for Claude desktop app's Cowork mode. Key insight: most people use Claude like a "vending machine" (one-off prompts) and then blame inconsistent outputs, when the real issue is lack of systematic context upfront.

## The 4-Folder Structure

Basia recommends creating:
1. **ABOUT ME** — identity/role definitions
2. **PROJECTS** — active work contexts
3. **TEMPLATES** — reusable formats
4. **CLAUDE OUTPUTS** — work products

## Two Core Files

Before recurring work, write:
1. **Identity file** — who you are, your role, your domain
2. **Writing rules** — "anti-AI-style guide" defining what good output looks like for your specific voice/workflow

## Relevance to Robert's Practice

**Already implemented:**
- `CLAUDE.md` per project = PROJECTS folder equivalent
- `skills/writing_voice_robert.md` = the "anti-AI-style guide"
- `skills/` directory = TEMPLATES folder (reusable knowledge)
- `drafts/` + `output_log.md` = CLAUDE OUTPUTS tracking

**Key validation:** The emphasis on **anti-AI-style guides** (explicitly defining what NOT to do) aligns with Robert's DO NOT rules in `writing_voice_robert.md` (no emdashes, no "delve", no "I hope this finds you well", etc).
