01 Why a slice first /////

The hard part is content and memory, so we test that first.

A full mobile port is a large commitment, and the risk is not in the code. It is in content and memory: roughly 156 GB of desktop-authored assets against a 2 to 3 GB device budget, a desktop renderer (Nanite, Lumen, VSM, TSR) that has no mobile equivalent, and at least one plugin whose runtime status on mobile is unconfirmed. These unknowns are what keep a full-port number a range rather than a fixed figure.

This phase resolves them. Over 12 man-months across a six-month calendar we stand up the mobile pipeline, downshift the renderer, and bring one full region onto a real device inside the memory budget. We record what the optimisation costs per asset class and extrapolate that across the game. The phase delivers a working slice and a full-port plan costed from measured data.

In short: a fixed, contained phase that tests the three things driving the full-port range, ending at month four with a working build on device and a go / no-go on the full port.

02 What the slice proves /////

Three streams of work, measured on one region.

We take the starting region end to end and treat it as the sample the full game is costed from. Each stream produces measured figures we can extrapolate to the rest of the content.

Severe

Content & memory

The core of the phase. We process the heaviest assets on the slice: 8K MetaHuman faces to 512, Nanite hero meshes to LOD chains, project-wide texture and LODGroup caps, ASTC. We record the cost per asset class and the on-device memory we reach, which is what a full-game budget is built from.

High

Renderer downshift

Moving the slice to the mobile feature level: baked lightmaps and reflection captures, CSM and static shadows, MSAA or FXAA. The existing Lumen-off scalability bucket is the starting point. Once it works on the slice, the same settings carry across the game.

Moderate

Pipeline & blockers

The automation needed to handle 156 GB at scale: CI, an automated cook, and on-demand asset delivery (ODR / PAD). Plus the spikes that clear unknowns early, the Narrative-plugin runtime recompile and a touch-control baseline, so blockers surface during this phase rather than mid-port.

04 Roadmap /////

The six-month schedule, month by month.

Month 1 // Proof of life
Boot on device

iOS + Android targets added, mobile device profiles, plugins stripped, Narrative recompile spike, CI standing up. One map plus a player MetaHuman booting on a real target device, baseline memory and FPS captured.

Month 2 // Renderer
Mobile feature level

Baked lighting, CSM, reflection captures, RVT decision. Content pipeline kickoff: texture and LODGroup caps, ASTC. Tech-art and build seats both on.

Month 3 // Pipeline
Automation & offenders

Automated cook and ODR / PAD live; dev-junk culled via allowlist cook. Biggest offenders processed: faces to 512, Nanite to LOD chains. Per-asset cost captured. Build seat completes.

Month 4 Gate
Region in budget

One full region inside the memory budget on a target device, touch controls and camera, ODR / PAD wired. The go / no-go checkpoint for the full port.

Month 5 // Measure
Profile & extrapolate

Profile across the device matrix, re-tune world streaming on the slice, capture thermal and sustained-performance data. Turn slice numbers into a costed full-game plan.

Month 6 // Package
Decision package

Full-port estimate refreshed from measured data, slice build and technical report delivered, open items closed. The output is the decision package for the full port.

05 Commercials /////

Fixed scope, milestone-based.

A fixed-price phase with payment tied to accepted milestones and a gate at month four. All code, art and tooling produced in the phase transfer to Blue Scarab on delivery.

  • What it includes. The four seats below, the slice build, the standing pipeline (CI, automated cook, ODR / PAD), and the refreshed full-port estimate built on measured data. Development QA runs inside the team.
  • The M4 gate. If the region does not hold inside the memory budget on target hardware, that is a result in itself, reached before the full-port spend is committed.
  • Carries into the port. The pipeline, the renderer profile and the optimised slice become the first deliverables of the full port if you greenlight it; none of the phase work is discarded.
  • Credited toward the port. The phase is the first tranche of the full port rather than a separate cost. If you greenlight, the spend counts toward the full-port budget and the slice deliverables are the port's first deliverables.
  • Pass-through at cost. AI tooling, QA device hardware, Apple and Play developer fees. Unreal engine license fees are the client's.
  • Assumptions. Premium device floor (iOS A15+, Android 8 GB / Snapdragon 8-series); Perforce and build access in place at kickoff, as today.

Leaner option // Core slice, 9 man-months
900,000 SEK
Lead porting engineer, tech artist and the contingency seat. It still tests content, memory and the renderer on one region and reaches the M4 go / no-go.

The difference from the full slice: the production pipeline (CI, automated cook, ODR / PAD) is built later, during the port itself, rather than up front. The contingency seat stays, given the project's risk level. The core risks are still tested on the slice, but the at-scale automation moves into the port, which makes the full-port ramp slower. For a project of this risk we would run the full slice; the core slice is the lighter way in if budget is the constraint.

06 Risks & open questions /////

The things we are watching.

01The slice region is representative of the whole game

Mitigation // we pick the starting region together at kickoff so it carries the heavy asset classes (MetaHumans, hero meshes, open-world streaming). The per-asset costs we measure then extrapolate cleanly to the full content set.

02The Narrative plugin runtime on mobile (potential hard blocker)

Mitigation // a Month-1 recompile spike resolves it first, before any content work scales. If it needs a workaround, we know in week one of the phase, not month four of the port.

03Content optimisation cost landing where we expect

Mitigation // the whole point of the slice. Two senior seats on automation and tech art carry the offenders, and we report the achieved memory and per-class cost as the phase deliverable, so the full-port number is evidence-based.

Open questions // which region we take as the slice; UE upgrade target version; device matrix floor confirmation; whether EOS identity is in scope for the slice or deferred to the full port; kickoff date.
